# Clubtone TOP Player Fix 1.5.21

Восстанавливает воспроизведение в поддерживаемых TOP-списках Clubtone через Soundfiles, сохраняет штатный нижний плеер и заранее готовит три следующих аудиопотока. Общая история прослушиваний и открытых страниц отмечает ссылки на треки по всему сайту на clubtone.do.am и clubtone.net.

Автор: **Dmitriy Oshev**. Создан с помощью **Codex GPT**.

## Установка и обновление

Установите Tampermonkey, затем [откройте скрипт](https://raw.githubusercontent.com/Emparda/clubtone-top-player-fix/refs/heads/main/clubtone-player-fix.user.js) и подтвердите установку/обновление. Эта ссылка начнёт выдавать 1.5.21 после публикации файлов владельцем репозитория. До публикации можно установить приложенный `clubtone-player-fix.user.js` или заменить код существующего скрипта содержимым `.txt`.

Обновляйте **существующий** скрипт, не удаляя его и не создавая вторую активную копию. Имя и namespace сохранены. Если ранее был установлен History Companion, он не нужен и должен оставаться отключённым. После обновления перезагрузите ранее открытые страницы Clubtone, чтобы они использовали одинаковую версию.

Дальнейшая проверка версии идёт через `@updateURL`, загрузка — через `@downloadURL`. Автоматическая проверка и установка зависят от настроек Tampermonkey. Новых разрешений расширения эта версия не добавляет.

## Управление

- **A** — предыдущий трек; **S** — Play/Pause; **D** — следующий.
- **W** — страница текущего трека на используемом зеркале.
- **F** — страница скачивания Soundfiles.

Горячие клавиши не перехватываются при вводе текста. Пауза на обложке — две полоски без окружности. Работа истории по всему сайту не означает поддержку воспроизведения во всех сторонних плеерах сайта.

## История в этой версии

История остаётся внутри хранилища этого скрипта в Tampermonkey. Вместо одного постоянно перезаписываемого массива используются до 256 блоков:

`clubtone-played-v3-00` … `clubtone-played-v3-ff`.

Это ключи базы расширения, **не 256 отдельных файлов Windows**. ID распределяются по блокам автоматически. Обычное добавление трека затрагивает один блок; при открытии страницы читаются блоки, к которым относятся её ссылки. Старые прослушивания не удаляются по возрасту или лимиту количества.

`clubtone-played-v2` сохраняется как исходная резервная копия. Перенос выполняется автоматически, по частям, с проверкой записи. Маркер `clubtone-played-v3-migration` появляется после успешного переноса; незавершённый перенос можно продолжить при следующем открытии страницы. Исходная копия не обновляется новыми прослушиваниями версии 1.5.21, поэтому простой откат на 1.5.19 не покажет более новые отметки. При возврате к 1.5.21 новые блоки снова используются.

**Первый перенос большой истории занимает время и временно увеличивает объём хранения**, поскольку старая копия остаётся. При миллионе ID полный тест переноса с проверкой занял примерно 23 секунды; часть работы отдаёт управление между порциями. Первоначальное чтение старого массива и его объединение также может задержать первый запуск. После завершённого переноса старый массив больше не читается при обычном запуске.

Сохраняется связка с браузером: реальное открытие страницы учитывается браузером и скриптом; успешное событие `playing` отмечает общую историю и использует штатный приём сайта с `replaceState` для текущего origin. Служебные вкладки не открываются. Собственная история обеспечивает отметки второго зеркала; браузерный `:visited` не становится общим для разных доменов.

Изменения открытых вкладок объединяются. При ошибке хранилища несохранённые отметки остаются в памяти и повторяются через 15 секунд. GM API не предоставляет атомарную транзакцию между вкладками: одновременное аварийное закрытие всех конкурирующих вкладок или завершение браузера до успешной записи не покрывается гарантией сохранности. При длительном отказе записи закрытие вкладки также может потерять ещё не записанное изменение.

Скрипт не отправляет список истории на GitHub или отдельный сервер. При воспроизведении остаются обычные запросы к Clubtone и Soundfiles, при обновлениях — к GitHub. Настройки синхронизации/резервного копирования самого расширения находятся вне управления этого скрипта.

## Исправления после аудита 1.5.19

- Восстановление `.net` использует ID из ссылки или `entryID…`, а не позицию в рейтинге. Если ID неизвестен или противоречив, строка не заменяется догадкой.
- Название, жанр, ссылка и обложка создаются безопасными DOM-операциями. HTML и обработчики событий с зеркала не копируются. Добавлена проверка адресов и неожиданных перенаправлений ответа страницы.
- Отменённый первый `play()` не сбрасывает уже возобновлённый плеер. Подготовка следующих потоков запускается по фактическому `playing`.
- Ошибка записи истории больше не теряет возможность повторного сохранения того же ID. Неизменённые данные не записываются заново.
- При ошибке аудио 2/3/4 страница трека перечитывается для обновления `sffile`. Не более одной автоматической попытки на трек в минуту; переключение пользователя отменяет применение устаревшего результата.
- Вспомогательный кэш ссылок Soundfiles ограничен 4096 записями. Удалённая из кэша ссылка восстанавливается при необходимости; **историю прослушиваний этот лимит не затрагивает**.
- Сохранены предзагрузка трёх потоков, громкость, waveform, горячие клавиши, встроенная иконка скрипта и прежний regex-include. Настройки иконок доменов в панели Tampermonkey не менялись.

## Проверки

Пройдены 13 сценариев аудио-стресс-теста: в том числе 1000 переключений подготовленных потоков, 500 конкурирующих выборов и 200 задержанных запусков. Добавлены отдельные тесты ошибок аудита, переноса и повторного сохранения истории, одновременной записи двух зеркал в один блок, 100 замен списка до первого кадра, очистки индекса 10000 удалённых ссылок, восстановления устаревшего файла и смены трека во время восстановления.

Перенос миллиона ID проверен по каждому ID, исходный массив остался неизменным. В синтетическом Node-тесте с копированием значений GM чтение/добавление/проверка одного блока при миллионе ID заняли медианно около **60 мс** (95-й процентиль около 74 мс), запись содержала максимум 4148 ID. Это не замер дисковой базы установленного Tampermonkey и не обещание одинакового времени на всех компьютерах.

В изолированном Chrome проверены настоящий HTMLAudioElement, повторное использование подготовленного Audio и браузерный `:visited` после перезапуска. Звук тестовый; GM API и ответы страниц заменены тестовыми реализациями. Проверка в настоящем пользовательском Tampermonkey с сетевым Soundfiles остаётся необходимой перед массовым распространением.
